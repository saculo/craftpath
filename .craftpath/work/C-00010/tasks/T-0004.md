# T-0004 — Plan step loads the planning principles instead of naming skills

- **Work:** C-00010
- **Type:** feat
- **Wave:** 4
- **Depends on:** T-0001
- **Touches:** assets/steps/plan.md, test/init/init.test.ts
- **Scenarios:** S4

## Acceptance criteria

- **A1** Given a project initialised with `--harness claude-code,pi`, when the installed `craftpath-plan` step is read on either harness, then the text before its first numbered instruction, whitespace collapsed, contains "Load the `foundational-thinking` skill" and "Load the `sequence-verifiable-units` skill" — proven by integration test `plan loads the foundational and sequencing principles before its work`
- **A2** Given the same install, the installed `craftpath-plan` step on either harness contains neither "Skills for the implementer" nor "Name what the implementer needs in the task's Notes", and contains none of `` `backend` ``, `` `frontend` `` or `` `infrastructure` `` (backticked) — proven by integration test `plan no longer tells the planner to name skills in Notes`
- **A3** Given the same install, the installed `craftpath-plan` step on either harness contains none of `fix-root-causes`, `boundary-discipline` or `laziness-protocol` — proven by integration test `plan loads no implementer-only principle`

## Notes

- Delete the whole `### Skills for the implementer` subsection of
  `assets/steps/plan.md`, including its "three discipline skills" sizing hint.
  The `## Notes` section of the task template stays as it is (spec, Out of
  scope); the plan step may still tell the planner to record a local decision in
  Notes ("When a decision is still open") -- only naming skills there goes.
- Keep the existing "Load the `never-block-on-the-human`/`test-first` skill"
  lines; existing tests check them.
- The plan step itself is this work item's own planner: the copy installed in
  the main checkout is untouched until this branch merges.
- After changing `assets/`, run `bun bin/craftpath.ts init` in the worktree so
  the tracked installed copies under `.claude/`, `.pi/` and `.craftpath/` (and
  `.craftpath/manifest.json`) follow, and commit them with the task -- as
  C-00009 did. Never edit those copies by hand.
- Implementation note: the A3 test (`plan loads no implementer-only
  principle`) passed on its first run. That is expected, because it guards
  against adding something the plan step never contained. To prove it can fail,
  `laziness-protocol` was added to `assets/steps/plan.md` for one run: the test
  went red, and the change was then reverted. A1 and A2 failed first for the
  missing behaviour.
- The plan step now loads four skills in its preamble, each on its own "Load
  the ... skill before you do anything else." line. This follows the existing
  lines and the review step's pattern.
