## Acceptance criteria

- **A1** Given a project with no craftpath, when `init(root, ["--harness", "claude-code,pi"])` runs, then each of `.claude/skills/<name>/SKILL.md` and `.pi/skills/<name>/SKILL.md` exists for `fix-root-causes`, `boundary-discipline`, `laziness-protocol`, `foundational-thinking` and `sequence-verifiable-units`, its front-matter `name` equals the folder name and its `description` is non-empty — proven by integration test `installs the five engineering principles on both harnesses`
- **A2** Given the same install, each installed principle, compared word by word (whitespace collapsed), contains its statement: `fix-root-causes` "the cause, not the symptom"; `boundary-discipline` "inside the boundary its task owns"; `laziness-protocol` "the smallest change that meets the criteria" and "prefer deletion to addition"; `foundational-thinking` "settle the data shapes first" and "build the scaffold before the detail"; `sequence-verifiable-units` "verifiable on its own" — proven by integration test `each engineering principle states its principle`
- **A3** Given the same install, none of the ten installed principle files contains `{{` — proven by integration test `no engineering principle keeps a placeholder`
- **A4** Given the same install, no installed principle contains `disable-model-invocation: true` or `context: fork`, and no `craftpath-<name>` folder exists for any of them: they are skills the model loads, not steps the user runs — proven by integration test `the engineering principles are skills the model loads`
