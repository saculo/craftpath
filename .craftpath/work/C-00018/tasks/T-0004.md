# T-0004 — Guard that init and doctor ignore the tools

- **Work:** C-00018
- **Type:** test
- **Wave:** 4
- **Depends on:** T-0001
- **Touches:** `test/init/init.test.ts`, `test/doctor/doctor.test.ts`
- **Scenarios:** S7

## Acceptance criteria


- **A1** Given a PATH containing none of `rg`, `fd`, `zoxide`, `ast-grep`, `sg`, when `init` runs, then it exits 0, its output names none of the five, and no file other than the packaged skills, steps, scripts and settings is written — proven by integration test `init on a machine without the search tools installs nothing about them`
- **A2** Given the same PATH, when `doctor` runs on a healthy project, then its output contains no line mentioning the five tools and its exit code is 0 — proven by integration test `doctor says nothing about the search tools when they are absent`
- **A3** Given the same PATH, when a step's guard script runs for a ready work item, then it does not refuse for a missing tool — proven by integration test `a step guard does not refuse because a search tool is absent`

## Notes

- These are guard tests for behaviour that must stay unchanged, so they are expected to pass on first run: no failing RED exists because nothing is added. To see each can fail, temporarily make the code do the forbidden thing (e.g. a doctor line for `rg`), watch the test fail, then revert. Record that in the commit.
- Build the restricted PATH from a scratch bin dir holding only `python3`, `git` and `bun`'s directory entries, as the doctor tests do for python3 (`PATH: \`${bin}:...\``); the implementer chooses the construction.
- Existing guard tests live under `test/steps/`; reuse their helper for A3.
- Guard tests, green on first run by design. Each was seen to fail by temporarily making the code do the forbidden thing, then reverted: a `warn  rg not found` line in `src/doctor.ts` failed the doctor test; a `fd not found` line in `src/init.ts` output failed the init test; a guard.py that denies when `rg` is absent (via `shutil.which`) failed the guard test. Working tree verified clean of those edits.
- The restricted PATH is a scratch dir with symlinks to python3, git, bun, sh and env (`barePath()`, duplicated in both files since only the two test files are in Touches). rg/fd/zoxide/ast-grep/sg are installed on this machine, so the restriction is real.
- A3 lives in `test/init/init.test.ts` and spawns `guard.py` itself with an explicit `env`: the kit's `guard` helper takes no env, and setting `process.env.PATH` does not reach `Bun.spawn` children (checked), so reusing the helper would have tested nothing. `test/steps/kit.ts` is outside Touches, so it was left alone; a later task could give `guard` an env option.
- A1's "no other file written" is proven by comparing the file list of an init under the bare PATH with an init under the normal PATH.
