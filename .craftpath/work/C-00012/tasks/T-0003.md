# T-0003 — Detect JavaScript module checks

- **Work:** C-00012
- **Type:** feat
- **Wave:** 3
- **Depends on:** none
- **Touches:** src/detect.ts, src/init.ts, test/init/init.test.ts
- **Scenarios:** S7, S8, S9

## Acceptance criteria

- **A1** Given a project without `.craftpath/config.toml` has `package.json` scripts `lint` and `typecheck` but no `check`, when `craftpath init` creates its configuration, then `[modules.app]` has `check = "bun run lint && bun run typecheck"` — proven by integration test `fresh init combines JavaScript lint and typecheck scripts into a module check`
- **A2** Given a project without `.craftpath/config.toml` has `package.json` scripts `check`, `lint`, and `typecheck`, when `craftpath init` creates its configuration, then `[modules.app]` has exactly `check = "bun run check"`, not a command invoking lint or typecheck separately — proven by integration test `fresh init prefers a JavaScript check script`
- **A3** Given a project without `.craftpath/config.toml` has `package.json` with none of `check`, `lint`, or `typecheck`, when `craftpath init` creates its configuration, then `[modules.app]` has no `check` key — proven by integration test `fresh init omits an undetected module check`
- **A4** Given a project already has `.craftpath/config.toml` containing `check = "my-check"`, when `craftpath init` runs, then that configuration remains byte-for-byte unchanged — proven by integration test `init never replaces an existing module check configuration`

## Notes

- Extend the detected command shape with an optional check. For JavaScript,
  prefer declared `check`; otherwise require both declared `lint` and
  `typecheck`; do not infer checks for other ecosystems.
- The existing write-once config boundary supplies A4; retain it rather than
  adding an update path. Write each named integration test first and observe
  RED before production changes.
