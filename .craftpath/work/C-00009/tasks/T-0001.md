# T-0001 — Carry DECISIONS.md into the pull request body

- **Work:** C-00009
- **Type:** feat
- **Wave:** 1
- **Depends on:** none
- **Touches:** `assets/scripts/pr.py`, `test/steps/pr.test.ts`, installed copy `.craftpath/scripts/pr.py`

## Acceptance criteria

- **A1** Given a reviewed work item whose `DECISIONS.md` is `# C-00001 — Decisions`, then `## T-0001 — Add the endpoint` with the bullet `- Named the route /health -- it matches the spec`, then `## T-0002 — Document it` with `None` underneath, when `pr.py <work id>` opens the pull request, then the body passed to `gh pr create` contains a `## Decisions` section whose text is exactly `### T-0001 — Add the endpoint`, the bullet, `### T-0002 — Document it` and `None`, in that order, and the next `##` heading after `## Tasks` is `## Decisions` — proven by integration test `D1 the body carries the recorded decisions under Decisions, right after Tasks`
- **A2** Given the same work item, when `pr.py <work id>` opens the pull request, then the body contains no line `# C-00001 — Decisions`, no line starting `# `, and no line `## T-0001 — Add the endpoint` or `## T-0002 — Document it` (the task headings appear only at `###`) — proven by integration test `D1 drops the decisions file's own title and nests its task headings`
- **A3** Given one work item opened once without `DECISIONS.md` and then, after `DECISIONS.md` above is written and committed, opened again, when the two bodies are compared, then the second body is exactly the first with `## Decisions\n\n<the section text from A1>\n\n` inserted immediately before `## Review` — every other character (Problem, Scenarios, Tasks, Review, Knowledge, Out of scope) unchanged — proven by integration test `D1 changes nothing in the body but adding the Decisions section`
- **A4** Given a reviewed work item with no `DECISIONS.md`, when `pr.py <work id>` opens the pull request, then it exits 0, the body has no line `## Decisions` and no line starting `### T-`, its `##` headings are exactly `Problem`, `Scenarios`, `Tasks`, `Review`, `Out of scope` in that order, and no `DECISIONS.md` exists in the work directory afterwards — proven by integration test `D2 without DECISIONS.md, the body has no Decisions section`

## Notes

Skill: `backend` (a CLI script; the tests drive `pr.py` as a subprocess through the existing `pr(tree, stub)` helper and read the body from the gh stub's `body.md`).

- The tests go in the `pr.py -- commit the review, push, open the pull request` describe of `test/steps/pr.test.ts`. Write `DECISIONS.md` at `.craftpath/work/C-00001/DECISIONS.md` in the worktree and commit it with a `docs(C-00001): add decisions` commit (as the review step does) before running `pr.py`; a docs-only commit in the work item's folder does not touch the Tasks list, which only greps `(C-00001/T-…)` commits. The fixture plan has one task, T-0001; the T-0002 heading in `DECISIONS.md` is carried over anyway, because the body copies the file, it does not match headings to the plan.
- A3: run `pr.py` twice on the same tree, copying `body.md` after the first run. The stub has no `existing` file, so the second run opens again; commit hashes in Tasks are identical across the two runs because the task commits are the same. The second run makes no REVIEW.md commit, since `commit_files` skips a file that is already committed and unchanged.
- Order to see each test fail for the right reason: A1, A2 and A3 fail today (no section). A4 passes against today's code. Write A1 first and make it pass with the simplest code -- reading `DECISIONS.md` unconditionally -- then write A4 and watch it fail (pr.py crashes or emits the section on a missing file), then add the existence check. Do not skip that order.
- Decision: transform the file by dropping every line that starts with `# ` and turning a leading `## ` into `### `; every other line, bullets and `None` included, is copied as is, then stripped of leading and trailing blank lines. Alternative: parse it with `checks.sections()` and rebuild it heading by heading. Reason: the spec says the content is carried word for word, and a line rewrite cannot reorder or drop anything a parse-and-rebuild might, e.g. a ` (stuck)` suffix on a heading.
- Decision: update the `pr.py` docstring to name `DECISIONS.md` among the files the body is built from, but leave `assets/steps/pr.md` as it is. Alternative: also name it in the step text. Reason: the step agent never reads the body's sources, and the invariant test `only work, which writes DECISIONS.md, and review and learn, which read it, name it` in `test/steps/work.test.ts` pins which steps may name the file; widening it is out of this experiment's scope.
- After GREEN, run `bun bin/craftpath.ts init` in the worktree so `.craftpath/scripts/pr.py` matches `assets/` (CLAUDE.md: change `assets/`, never the copies). Keep only that copy and its hash in `.craftpath/manifest.json`; restore any other copy `init` refreshes, as it is outside this task's Touches.
- The existing tests P3--P6 and L10 must stay green unchanged.
