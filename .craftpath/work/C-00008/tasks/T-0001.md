# T-0001 — List DECISIONS.md among what review prints

- **Work:** C-00008
- **Type:** feat
- **Wave:** 1
- **Depends on:** none
- **Touches:** `assets/scripts/review.py`, `test/steps/review.test.ts`, installed copy `.craftpath/scripts/review.py`
- **Scenarios:** S1, S2

## Acceptance criteria

- **A1** Given a work item whose tasks are all done and committed with tests green, and an uncommitted `DECISIONS.md` in its work directory, when `review.py <work id>` runs, then it exits 0, prints the line `  decisions: <absolute path of DECISIONS.md>` directly after the `  plan:` line, and makes exactly one commit `docs(C-00001): add decisions` containing only `DECISIONS.md` — proven by integration test `names DECISIONS.md among what to review, next to the spec and the plan`
- **A2** Given the same work item with `DECISIONS.md` already committed by an earlier run, when `review.py <work id>` runs again, then it exits 0, still prints `  decisions: <absolute path of DECISIONS.md>` directly after the `  plan:` line, and makes no new commit — proven by integration test `names an already committed DECISIONS.md again on a re-review`
- **A3** Given the same work item with no `DECISIONS.md`, when `review.py <work id>` runs, then it exits 0, creates `REVIEW.md`, prints `  spec:` and `  plan:` as usual, its stdout contains no `DECISIONS.md`, its stderr is empty, and no `DECISIONS.md` exists in the work directory afterwards — proven by integration test `without DECISIONS.md, names none and creates none`

## Notes

Skill: `backend` (a CLI script; the tests drive it as a subprocess through `script()` in `test/steps/kit.ts`).

- The tests go in the `review.py -- tests first, then REVIEW.md` describe of `test/steps/review.test.ts`, next to the existing DECISIONS.md tests, reusing their `decisions(tree)` and `DECISIONS` helpers.
- A3 passes against today's code, since review.py names no path yet. Seeing it fail is part of the cycle: write A1 first and make it pass with the simplest code (printing the line unconditionally), then write A3 and watch it fail on the printed path, then add the existence check. Do not skip that order: it is the only way to see A3 fail for the right reason.
- Decision: the label is `decisions:`, aligned with `review:`, `spec:`, `plan:` in the "Work item" block. Alternative: a different label, to avoid confusion with the existing `  decisions: <sha> <subject>` line printed above the block when the file is committed. Reason: the block already labels each file by its role; the commit line stays as it is (its existing test checks only the subject) and sits before the header, so the two do not read as one list.
- The existing tests `commits an uncommitted DECISIONS.md alone as the decisions`, `without DECISIONS.md, makes no decisions commit` and the invariant `review is the only script that names DECISIONS.md` must stay green unchanged.
- After GREEN, run `bun bin/craftpath.ts init` in the worktree so the installed `.craftpath/scripts/review.py` matches `assets/` (CLAUDE.md: change `assets/`, never the copies).
