# T-0004 — Check fix tasks leave finished work untouched

- **Work:** C-00013
- **Type:** feat
- **Wave:** 4
- **Depends on:** T-0003
- **Touches:** assets/scripts/checks.py, test/steps/review-fix.test.ts
- **Scenarios:** S3, S5, S6

## Acceptance criteria

- **A1** Given ticked, committed T-0001, a committed `REVIEW.md` whose only open point is R1, and `PLAN.md` and `tasks/` identical to HEAD (no task added), when `check.py review-fix C-00001` runs, then it exits 0 — proven by integration test `adding no fix task passes the review-fix check`
- **A2** Given ticked, committed T-0001 and a new fix task for R1, and `tasks/T-0001.md` with one line appended since HEAD, when `check.py review-fix C-00001` runs, then it exits 1 and names `T-0001` as changed — proven by integration test `an edited finished task file fails the review-fix check`
- **A3** Given ticked, committed T-0001 and a new fix task for R1, and T-0001's line in `PLAN.md` turned from `- [x]` back to `- [ ]`, when `check.py review-fix C-00001` runs, then it exits 1 and names `T-0001` as changed — proven by integration test `a reopened finished task fails the review-fix check`
- **A4** Given a committed `REVIEW.md` with R1 open and a new fix task for R1, and `REVIEW.md` edited since HEAD (R1 reworded), when `check.py review-fix C-00001` runs, then it exits 1 and names `REVIEW.md` as changed — proven by integration test `an edited review fails the review-fix check`

## Notes

- Extends `check_review_fix` from T-0003. A task already in HEAD's `PLAN.md`
  must keep its exact line and its task file byte-for-byte (`git show
  HEAD:<path>`); a task removed from `PLAN.md` is a change too.
- `REVIEW.md` must equal HEAD's. review-fix.py (T-0002) commits it before the
  agent writes anything, so any difference is the agent's.
- A1 is S3: when every open point is untestable, the agent adds nothing and the
  check must not demand coverage. T-0003's coverage rule already skips the
  no-new-task case; A1 may therefore pass on first run -- prove it can fail by
  temporarily removing that skip, and record it in Notes.
- Implementation note: A1 passed the first time it ran, as expected. Its
  ability to fail was proven by temporarily replacing T-0003's `if not new:`
  skip with `if False:` -- the test then failed with `R1 is open, but no new
  task fixes it` -- and restoring it. A2-A4 each failed first with exit 0
  (the check accepted the change) before the code existed.
- The finished-work and REVIEW.md checks run before the no-new-task skip, so
  they also apply when review-fix adds nothing (S3).
- HEAD's text is read with a raw `git show` in `at_head`, not `craftpath.git`,
  because that helper strips its output, which would let a change in trailing
  newlines through and break the byte-for-byte comparison.
