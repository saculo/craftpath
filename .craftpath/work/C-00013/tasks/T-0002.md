# T-0002 — List open review points for fix tasks

- **Work:** C-00013
- **Type:** feat
- **Wave:** 2
- **Depends on:** none
- **Touches:** assets/scripts/review-fix.py, test/steps/review-fix.test.ts
- **Scenarios:** S4, S5, S7, S8

## Acceptance criteria

- **A1** Given a `REVIEW.md` with `R1` open, `R2` marked `[x]` and `R3` marked `[-]`, when `review-fix.py C-00001` runs, then its output contains R1's whole point line and contains neither `R2` nor `R3` — proven by integration test `review-fix.py lists only the open points`
- **A2** Given a plan whose last task is `T-0003`, ticked, in wave 2 (the highest wave), when `review-fix.py C-00001` runs, then its output has the lines `last task: T-0003`, `highest wave: 2` and `fix tasks start at wave 3`, and the `task.py` command it prints carries `--type fix` — proven by integration test `review-fix.py says where the fix tasks go`
- **A3** Given an uncommitted `REVIEW.md` with an open point, when `review-fix.py C-00001` runs, then exactly one new commit exists, `docs(C-00001): add review`, changing only `REVIEW.md`; `REVIEW.md`, `PLAN.md` and every task file are byte-for-byte as before — proven by integration test `review-fix.py commits the review and writes nothing else`
- **A4** Given a `REVIEW.md` already committed, when `review-fix.py C-00001` runs, then HEAD is unchanged and `git status --porcelain` is empty — proven by integration test `review-fix.py makes no commit when the review is committed`
- **A5** Given C-00001 with ticked, committed T-0001 and an open point R1, when `review-fix.py C-00001` runs, `task.py C-00001 --wave 2 --type fix "<title>"` adds T-0002 (filled with `- **Fixes:** R1`), and then `work.py C-00001 all` runs, then work's output lists `T-0002` and does not list `T-0001` — proven by e2e test `work runs only the fix tasks review-fix added`

## Notes

- Shape: `review-fix.py <work id>` runs after T-0001's guard. It commits
  `REVIEW.md` with `commit_files(work, work_id, "review", [REVIEW.md])` -- the
  same "each step commits the step before it" pattern as plan.py and work.py --
  then prints the work item, the paths of `SPEC.md`, `PLAN.md`, `REVIEW.md` and
  `tasks/`, the open point lines, the three lines of A2 and the `task.py`
  command. It never writes `PLAN.md` or a task file.
- Decision: the script commits `REVIEW.md`. Alternative: leave it uncommitted
  and snapshot it elsewhere. Reason: review.py leaves a review with open points
  uncommitted, and the check of T-0004 needs a committed `REVIEW.md` to prove
  the step left it unchanged (S5); a `docs(...): add review` commit is not a task
  commit, so S7 holds.
- "Last task" is the highest `T-xxxx` in `PLAN.md`, the same numbering task.py
  uses; "highest wave" is the highest `### Wave` with a task.
- A5 is the S8 hand-off. `work.py` already lists only open tasks, so once
  review-fix.py exists this test may go green without production code. Prove it
  can fail: temporarily drop the `line.startswith("- [ ]")` filter in work.py,
  see the test fail on `T-0001` being listed, restore it. Record that in Notes.
