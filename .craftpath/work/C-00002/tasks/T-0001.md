# T-0001 — Apply pi step settings

- **Work:** C-00002
- **Type:** feat
- **Wave:** 1
- **Depends on:** none
- **Touches:** app
- **Scenarios:** S1, S2, S3, S4, S5

## Acceptance criteria

- **A1** Given `.craftpath/config.toml` contains `[steps.review.pi]` with `model = "anthropic/claude-opus-5-5"` and `effort = "high"`, when `craftpath init --harness pi` installs the pi review step, then `.pi/skills/craftpath-review/SKILL.md` instructs the native pi `Agent` call to use model `anthropic/claude-opus-5-5` and the pi thinking level translated from `high`, and it does not leave that review subagent on only the session model — proven by integration test `a configured pi step runs its subagent with model and thinking level`
- **A2** Given `.craftpath/config.toml` contains `[steps.review.pi]` with `model = "anthropic/claude-opus-5-5"`, when `craftpath init --harness pi` installs the pi review step, then `.pi/skills/craftpath-review/SKILL.md` invokes review through the native pi `Agent` tool and does not contain `claude -p`, a shell `claude` invocation, or instructions to use another CLI — proven by integration test `an Anthropic pi model is invoked through the Agent tool only`
- **A3** Given `.craftpath/config.toml` contains `[steps.work.pi]` with `model = "openai-codex/gpt-5.6-terra"` and `effort = "medium"`, when `craftpath init --harness pi` installs the pi work step, then `.pi/skills/craftpath-work/SKILL.md` still lacks front-matter model or effort overrides for the work step itself and its task-subagent Agent instruction includes model `openai-codex/gpt-5.6-terra` plus the pi thinking level translated from `medium` — proven by integration test `pi work starts task subagents with work model and thinking level`
- **A4** Given `.craftpath/config.toml` has no `[steps.<step>.pi]` table, when `craftpath init --harness pi` installs pi steps, then the installed pi skills match the current unconfigured output for model and thinking-level behavior: no model or thinking-level override is added — proven by integration test `a pi step without settings installs as before`
- **A5** Given a project has no `.craftpath/config.toml`, when `craftpath init` writes a fresh config, then it contains commented examples for `[steps.work.pi]` with `model = "openai-codex/gpt-5.6-terra"` and `[steps.review.pi]` with `model = "anthropic/claude-opus-5-5"`, includes commented `effort` keys for those pi examples, and TOML parsing does not produce active `steps.work.pi` or `steps.review.pi` settings — proven by integration test `a fresh config shows commented pi model examples`

## Notes

Use the `tdd` skill before implementation. This is a single task because the observable behavior is one coherent init/rendering change in module `app`: parsing already supports `[steps.<step>.pi]`, the same renderer must apply settings to both delegated pi steps and work task subagents, and the config example documents the supported shape. Keep Anthropic handling native to pi's `Agent`/`pi-subagents-lite`; do not add any shell CLI dependency.

Implemented with pi settings rendered into the native `Agent` instruction text: delegated pi steps receive model/thinking-level settings in the handoff paragraph, while the pi work step remains session-run and passes the same settings only through `{{SUBAGENT}}` to task subagents. The `effort` value is translated directly to the pi thinking level wording. Fresh config examples are commented, so TOML parsing leaves `steps` absent until the user opts in.
