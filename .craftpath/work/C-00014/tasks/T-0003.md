## Acceptance criteria

- **A1** Given a project without `.craftpath/config.toml` has `package.json` scripts `test`, `lint`, and `typecheck`, when `craftpath init` initializes it, then `[modules.app]` has `test = "bun run test"` and `check = "bun run lint && bun run typecheck"` — proven by integration test `fresh init combines JavaScript lint and typecheck scripts into a module check`
- **A2** Given a project without `.craftpath/config.toml` has `package.json` scripts `test`, `check`, `lint`, and `typecheck`, when `craftpath init` initializes it, then `[modules.app]` has exactly `check = "bun run check"` rather than a combined lint/typecheck command — proven by integration test `fresh init prefers a JavaScript check script`
- **A3** Given a project without `.craftpath/config.toml` has a `package.json` test script but no `check`, `lint`, or `typecheck` scripts, when `craftpath init` initializes it, then `[modules.app]` has its test command and no `check` key — proven by integration test `fresh init omits an undetected module check`
- **A4** Given `.craftpath/config.toml` already contains `check = "custom-check"` and `package.json` declares `test`, `lint`, and `typecheck`, when `craftpath init` runs again, then the configuration remains byte-for-byte unchanged and retains `custom-check` — proven by integration test `init never replaces an existing module check configuration`
