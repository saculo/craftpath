## Acceptance criteria

- **A1** Given a freshly initialized project, when its `spec.py` script creates a work item, then the new `SPEC.md` contains an `## Assumptions` section immediately before `## Open questions`, with guidance to record the spec agent's decisions and their reasons, and it does not place the assumptions section elsewhere — proven by integration test `new specifications put assumptions before open questions`
- **A2** Given a freshly initialized project, when its installed `craftpath-spec` skill is read, then its creation and revision instructions direct an uncertainty decided from the request and concerned code that does not change scope, intent, or user-visible behavior to `## Assumptions` with its reason, while directing an uncertainty that would change one of those product concerns to `## Open questions` for the user, and it does not tell the agent to send the former to the user — proven by integration test `the spec step separates assumptions from product questions`
- **A3** Given a work-item `SPEC.md` with all required sections, a recorded assumption, and `None` under `## Open questions`, when `check.py spec` and the plan guard evaluate it, then the check exits successfully and the guard permits planning, and neither treats the recorded assumption as an unresolved question — proven by integration test `a complete specification with assumptions does not block planning`
- **A4** Given a work-item `SPEC.md` that otherwise has complete required content but has no `## Assumptions` section, when `check.py spec` evaluates it, then it exits unsuccessfully and identifies the missing assumptions section, and it does not report the specification complete — proven by integration test `a specification missing assumptions is incomplete`
