# T-0002 — Work gathers each wave's decisions into DECISIONS.md

- **Work:** C-00005
- **Type:** feat
- **Wave:** 2
- **Depends on:** T-0001
- **Touches:** assets/steps/work.md, test/steps/work.test.ts
- **Scenarios:** S3, S4

## Acceptance criteria

- **A1** Given a fresh project, when `init --harness claude-code,pi` runs, then the installed `craftpath-work` skill, on both harnesses, has an instruction in the step's own part (before `## The brief for each task's subagent`) that contains `` `.craftpath/work/<work id>/DECISIONS.md` `` and `does not exist` (telling the step to create it then), and that instruction comes after the instruction that runs `complete.py` for the wave's tasks — proven by integration test `work writes a wave's decisions to DECISIONS.md once complete.py has run`
- **A2** Given a fresh project, when `init --harness claude-code,pi` runs, then the same instruction in the installed `craftpath-work` skill, on both harnesses, says the decisions go under one heading per task id holding that task's decisions or `None`, and that every task of the wave gets one, done or stuck: it contains `task id`, `` `None` ``, `done` and `stuck` — proven by integration test `work gives every task of the wave a heading in DECISIONS.md, done or stuck`
- **A3** Given a fresh project, when `init --harness claude-code,pi` runs, then the installed `craftpath-work` skill, on both harnesses, tells the step to append each wave's decisions after what `DECISIONS.md` already holds and never to rewrite or remove it: the instruction contains `append` and the phrase `never rewrite or remove` — proven by integration test `work appends to DECISIONS.md and never rewrites it`
