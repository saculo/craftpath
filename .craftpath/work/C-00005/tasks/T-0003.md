## Acceptance criteria

- **A1** Given C-00001 with every task done, every module's tests green, an uncommitted `.craftpath/work/C-00001/DECISIONS.md` and an uncommitted `.craftpath/work/C-00001/scratch.txt`, when `review.py C-00001` runs, then it exits 0, HEAD is a new commit with subject `docs(C-00001): add decisions` whose only file is `.craftpath/work/C-00001/DECISIONS.md`, and `scratch.txt` and the newly created `REVIEW.md` are still uncommitted — proven by integration test `commits an uncommitted DECISIONS.md alone as the decisions`
- **A2** Given C-00001 with every task done and an uncommitted `DECISIONS.md`, when a module's tests are red and `review.py C-00001` runs, then it exits 1, HEAD is unchanged, and `DECISIONS.md` is still uncommitted — proven by integration test `with tests red, leaves DECISIONS.md uncommitted`
- **A3** Given C-00001 with every task done and no `DECISIONS.md`, when `review.py C-00001` runs, then it exits 0 and no commit with subject `docs(C-00001): add decisions` exists — proven by integration test `without DECISIONS.md, makes no decisions commit`
- **A4** Given C-00001 whose `DECISIONS.md` is committed and unchanged, when `review.py C-00001` runs, then it exits 0 and HEAD is unchanged — proven by integration test `with DECISIONS.md already committed, makes no decisions commit`
- **A5** Given the scripts in `assets/scripts/`, when each is searched for `DECISIONS.md`, then `review.py` is the only one that contains it (`complete.py` does not) — proven by integration test `review is the only script that names DECISIONS.md`
- **A6** Given a project installed with an earlier release -- a copy of `assets/` with every line containing `DECISIONS` removed from `steps/work.md` and `scripts/review.py` -- in which the user then edited `.craftpath/templates/SPEC.md`, when `init --harness claude-code` runs with the current assets, then the installed `.claude/skills/craftpath-work/SKILL.md` and `.craftpath/scripts/review.py` both contain `DECISIONS.md`, and the edited template is left byte-for-byte as the user wrote it — proven by integration test `re-running init brings the decisions record without overwriting your edits`

## Notes

- Skills: `backend`.
- In `review.py`, right after `run_tests(...)` succeeds and before REVIEW.md is
  handled: `commit_files(work, work_id, "decisions", [work / "DECISIONS.md"])`.
  `commit_files` already skips a missing file and an unchanged one (A3, A4)
  and commits only the paths it is given (A1). When it returns a commit,
  print it (e.g. `  decisions: <sha> <subject>`), as the other steps report
  what they committed.
- Order, decided here: the decisions commit comes before a closed review's
  `docs(<id>): add review` commit -- work before review, as the history reads.
  A1 uses a fresh REVIEW.md (left uncommitted), so the order only shows when
  both commit in one run; no criterion pins it.
- A1--A4 go in `test/steps/review.test.ts` under `describe("review.py --
  tests first, then REVIEW.md", ...)`, built from `done()` in
  `test/steps/kit.ts`; A2 breaks the tests the way V4 does. The review guard
  lets uncommitted files inside the work item's directory through (V3), so
  `DECISIONS.md` does not trip it; these tests call the script directly anyway.
- A3 and A4 guard behaviour `commit_files` already gives and may pass on their
  first run once A1 is green; if so, show each can fail (e.g. temporarily make
  the call ignore whether the file changed) and restore, and record that under
  Notes, as C-00003's T-0002 did.
- A5 is S7's script half; `complete.py` is not touched by this work item. The
  spec's accepted side effect (a module at `.` sweeping DECISIONS.md into a
  task commit) is not tested or fixed.
- A6 goes in `test/init/init.test.ts` under `describe("re-running init
  updates", ...)`, built like `re-running init adds the principle without
  overwriting your edits`: `cp` `assets/` to a scratch dir, strip the lines,
  assert the stripped copies no longer contain `DECISIONS`, install that, edit
  the SPEC.md template, then re-run `init` with the real assets. Its "kept"
  half already holds; the test fails before this task on `review.py`.
- Edit `assets/scripts/review.py`, never `.craftpath/scripts/review.py`.
