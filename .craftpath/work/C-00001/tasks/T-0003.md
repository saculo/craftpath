# T-0003 — Show the step settings commented out in a fresh config.toml

- **Work:** C-00001
- **Type:** feat
- **Wave:** 3
- **Depends on:** T-0001
- **Touches:** src/init.ts, README.md, test/init/init.test.ts
- **Scenarios:** S6

## Acceptance criteria

- **A1** Given a project with no `.craftpath/config.toml`, when `init --harness claude-code` runs, then the config.toml it writes contains the commented-out lines `# [steps.work.claude-code]`, `# model = "sonnet"`, `# [steps.review.claude-code]` and `# model = "opus"`, in that order, and `Bun.TOML.parse` of it has no `steps` key — proven by integration test `a fresh config shows the step settings commented out`
- **A2** Given a project with no `.craftpath/config.toml`, when `init --harness claude-code` runs, then every `.claude/skills/craftpath-<step>/SKILL.md` it installs is byte-for-byte the file installed in a project whose existing config.toml has no `[steps]` table — proven by integration test `the commented example applies nothing`
- **A3** Given a project whose `.craftpath/config.toml` already exists without the example, when `init --harness claude-code` runs, then config.toml is byte-for-byte unchanged and contains no `steps.` text — proven by integration test `an existing config is not given the example`
