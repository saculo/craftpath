# T-0002 — Pass work's configured settings to its task subagents

- **Work:** C-00001
- **Type:** feat
- **Wave:** 2
- **Depends on:** T-0001
- **Touches:** assets/steps/work.md, src/harness.ts, src/init.ts, test/init/init.test.ts
- **Scenarios:** S2, S3, S7

## Acceptance criteria

- **A1** Given a project whose config.toml has `[steps.work.claude-code]` with `model = "sonnet"` and `effort = "medium"`, when `init --harness claude-code` runs, then `.claude/skills/craftpath-work/SKILL.md` tells the step to start each task's subagent with the `Agent` tool using agent `general-purpose`, model `sonnet` and effort `medium` (the line reads ``with the `Agent` tool (agent `general-purpose`, model `sonnet`, effort `medium`)``) — proven by integration test `work starts its task subagents with work's model and effort`
- **A2** Given the same config as A1, when `init --harness claude-code` runs, then the front matter of `.claude/skills/craftpath-work/SKILL.md` has no line starting `model:` or `effort:` — proven by integration test `work itself keeps the session's model when work is configured`
- **A3** Given `[steps.work.claude-code]` with only `model = "sonnet"`, when `init --harness claude-code` runs, then the work skill's line reads ``with the `Agent` tool (agent `general-purpose`, model `sonnet`)`` and the file contains no `effort` — proven by integration test `work passes only the model when only the model is configured`
- **A4** Given a config.toml with no `[steps]` table, when `init --harness claude-code,pi` runs, then both installed work skills contain ``with the `Agent` tool (agent `general-purpose`)`` exactly as today, with nothing between `general-purpose` and the closing parenthesis — proven by integration test `work without a setting starts its subagents as before`
- **A5** Given `[steps.work.claude-code]` with `model = "sonnet"`, when `init --harness claude-code,pi` runs, then `.pi/skills/craftpath-work/SKILL.md` is byte-for-byte the file installed with no `[steps]` table — proven by integration test `a Claude Code work setting leaves pi's work step untouched`

## Notes

- Skills: `backend`.
- Add one token to `assets/steps/work.md`, at the Agent call:
  ``with the `Agent` tool (agent `general-purpose`{{SUBAGENT}})``. Claude Code
  renders it from work's settings as `, model \`MODEL\`` (MODEL being the configured value) and/or
  `, effort \`EFFORT\``, in that order; with no setting, and always on pi, it
  renders to the empty string -- so an unconfigured install is byte-identical to
  today (A4, S3). Document the token in the header comment of `src/harness.ts`
  with the others.
- The Claude Code `Agent` tool takes `model` and `effort` parameters; the
  rendered wording only has to make the step pass them. Do not put the setting
  in the brief text the subagent reads -- the subagent cannot change its own
  model.
- Reads the `[steps.<step>.claude-code]` table T-0001 introduced; do not add a
  second reader.
- Edit `assets/steps/work.md`, never the installed copy; after the task, the
  repo's own `.claude/` copies are refreshed with `bun bin/craftpath.ts init`
  only if the user asks -- not part of this task.
- Implementation notes (T-0002):
  - `{{SUBAGENT}}` is replaced in the shared `render()` (new trailing
    `subagent` parameter, default `""`), so pi, shared skills and every
    non-work step render it to nothing. Only Claude Code's `renderStep` for
    `work` passes `forSubagents(settings)`. That needed `renderStep` to call
    `render(...)` directly instead of `this.render(...)`.
  - `src/init.ts` needed no change: it already passes each harness its own
    `[steps.<step>.<harness>]` table (T-0001's reader).
  - RED: A1 and A3 failed on the missing wording. A2, A4 and A5 passed on
    the first run because they guard behaviour that already holds (T-0001
    keeps work's front matter clean; unconfigured output was already the
    old line). Each guard was then shown able to fail by breaking the code
    on purpose, and the code was restored afterwards: A2 by removing the work
    exclusion from the front matter; A4 by defaulting `subagent` to a
    non-empty string; A5 by having init hand pi the claude-code table and pi
    render `forSubagents`.
  - The repo's own `.claude/` copies were not refreshed (as the plan says).
