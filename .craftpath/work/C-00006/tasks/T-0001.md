## Acceptance criteria

- **A1** Given an empty project, when `init --harness claude-code,pi` runs, then `.claude/skills/test-first/SKILL.md` and `.pi/skills/test-first/SKILL.md` both exist, each with `name: test-first` and a non-empty `description` in its front matter and no `{{` left in it — proven by integration test `installs the test-first principle on both harnesses`
- **A2** Given an empty project, when `init --harness claude-code,pi` runs, then neither `.claude/skills/craftpath-test-first` nor `.pi/skills/craftpath-test-first` exists, and the installed `test-first` skill carries neither `disable-model-invocation: true` nor `context: fork` — proven by integration test `the test-first principle is a skill the model loads, not a step the user runs`
- **A3** Given a project initialised with `--harness claude-code`, when `.claude/skills/test-first/SKILL.md` is read, then it contains each of `before any code exists`, `RED`, `GREEN`, `REFACTOR`, `reproducing test`, `spike`, `Stop signals` and `complete.py`, and states that only the green half is enforced — proven by integration test `the test-first principle states what the tdd rule states`
- **A4** Given a project initialised with `--harness claude-code`, when `.claude/skills/test-first/SKILL.md` is read, then it states the prove-it-works check: a test counts only once it has been seen to fail because the behaviour is missing, and then seen to pass — proven by integration test `the test-first principle states the prove-it-works check`
