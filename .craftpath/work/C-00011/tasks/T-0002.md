# T-0002 — Require a known --type when adding a task

- **Work:** C-00011
- **Type:** feat
- **Wave:** 2
- **Depends on:** none
- **Touches:** assets/scripts/task.py, assets/templates/TASK.md, assets/steps/plan.md, test/steps/kit.ts, test/steps/plan.test.ts, .craftpath/scripts/task.py, .craftpath/templates/TASK.md, .claude/skills/craftpath-plan/SKILL.md, .pi/skills/craftpath-plan/SKILL.md, .craftpath/manifest.json
- **Scenarios:** S6, S7, S8

## Acceptance criteria

Every criterion starts from a plan for C-00001 created by `plan.py`, with
T-0001 and T-0002 added by `task.py`.

- **A1** When `task.py C-00001 --wave 1 "Add the length check"` runs with no `--type`, then it exits 1, prints a usage line containing `--wave <n> --type <type> "<title>"`, creates no tasks/T-0003.md, and leaves PLAN.md byte-for-byte unchanged — proven by integration test `adding a task without a type is refused with the usage`
- **A2** When `task.py C-00001 --wave 1 --type feature "Add the length check"` runs, then it exits 1, prints `the type must be one of feat, fix, test, refactor, docs, perf, chore`, creates no tasks/T-0003.md, and leaves PLAN.md byte-for-byte unchanged — proven by integration test `adding a task with an unknown type is refused`
- **A3** When `task.py C-00001 --wave 1 --type refactor "<a 46-character title>"` runs, then it exits 0, tasks/T-0003.md contains `- **Type:** refactor`, PLAN.md lists `- [ ] T-0003 — <that title>` under `### Wave 1`, and the output of `check.py plan C-00001` contains no `T-0003: Type` problem — proven by integration test `adding a task records its type in the task file`
- **A4** When `task.py --type docs C-00001 --wave 2 "Document the endpoint"` runs, with `--type` before the work id, then it exits 0 and tasks/T-0003.md contains `- **Type:** docs` — proven by integration test `--type is accepted anywhere among the arguments`
- **A5** Given a project installed by `craftpath init` for both harnesses, when the installed plan step is read, then `.claude/skills/craftpath-plan/SKILL.md` and `.pi/skills/craftpath-plan/SKILL.md` contain `task.py <work id> --wave <n> --type <type> "<task title>"` and no `--wave <n> "` without `--type` — proven by integration test `the plan step adds every task with its type`

## Notes

- Validate the type against `TYPES` imported from `assets/scripts/checks.py`,
  so `task.py` and `check.py plan` share one list (SPEC.md, Assumptions). Refuse
  before writing anything: number, file and PLAN.md come only after every
  argument is valid.
- Parse `--type <type>` the way `--wave <n>` is parsed: found anywhere, removed
  with its value, the rest is work id then title.
- Wording (decided here): the refusal for an unknown type is
  `the type must be one of feat, fix, test, refactor, docs, perf, chore` (a
  `Refusal`, exit 1); the usage line becomes
  `usage: task.py <work id> --wave <n> --type <type> "<title>"`.
- `assets/templates/TASK.md`: the Type line becomes `- **Type:** {{TYPE}}`,
  filled by `task.py` through `from_template`'s `{{KEY}}` values. Note that
  `from_template` reads the installed `.craftpath/templates/TASK.md`, so `init`
  must be re-run before the repo's own `task.py` writes the Type.
- `assets/steps/plan.md`: step 3 and the "The files" section call `task.py`
  with `--type <type>`; the Type row of the table says it is set by `task.py
  --type` and becomes the commit type. Leave the planning guidance otherwise
  alone.
- Existing callers break with this change and are updated in this task, not a
  later one: `planned()` in `test/steps/kit.ts` and every `script(root, "task",
  ...)` in `test/steps/plan.test.ts` pass `--type feat`. The test `an untouched
  task file is named with what is missing` asserts `Type` is named; once
  `task.py` writes the Type, assert on `Touches` instead.
  `test/steps/spec.test.ts`'s guard call with `C-00001 --wave 1 "x"` tests a
  refusal before any spec and does not need `--type`.
- No length check here: that is T-0003. This task does not depend on T-0001; it
  sits in wave 2 only because every task touches the single `app` module.
- After changing `assets/`, run `bun bin/craftpath.ts init` in the worktree so
  the tracked installed copies under `.claude/`, `.pi/` and `.craftpath/` (and
  `.craftpath/manifest.json`) follow, and commit them with the task. Never edit
  those copies by hand.
