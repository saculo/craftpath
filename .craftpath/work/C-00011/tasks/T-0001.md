- **Work:** C-00011
- **Type:** feat
- **Wave:** 1
- **Depends on:** none
- **Touches:** assets/scripts/checks.py, test/steps/plan.test.ts, test/steps/work.test.ts, .craftpath/scripts/checks.py, .craftpath/manifest.json

## Acceptance criteria

The fixture work item is `C-00001`, the same length as `C-00011`, so the
prefix `feat(C-00001/T-0002): ` is 22 characters and `refactor(...)` 26, as
in SPEC.md.

- **A1** Given a plan for C-00001 that `check.py plan` passes, whose T-0002 has Type `feat` and whose line in PLAN.md is then given a 51-character title (subject 73 characters), when `check.py plan C-00001` runs, then it exits 1, prints a problem naming T-0002 that contains `its commit subject would be 73 characters, limit 72`, does not print `PLAN.md is complete.`, and leaves PLAN.md and tasks/T-0002.md byte-for-byte as they were — proven by integration test `a task whose commit subject would pass 72 characters is named`
- **A2** Given the same plan with T-0002 of Type `feat` under a 50-character title (subject exactly 72 characters), when `check.py plan C-00001` runs, then it exits 0, prints `PLAN.md is complete.`, and its output does not contain `commit subject` — proven by integration test `a commit subject of exactly 72 characters passes the plan check`
- **A3** Given the same 50-character title but T-0002's Type edited to `refactor` in its task file (subject 76 characters), when `check.py plan C-00001` runs, then it exits 1 and prints a problem naming T-0002 that contains `its commit subject would be 76 characters, limit 72` — proven by integration test `the task's type counts towards its commit subject`
- **A4** Given T-0002 of Type `feat` added by `task.py` under a 40-character title, whose line in PLAN.md is then edited to a 51-character title while tasks/T-0002.md keeps its 40-character heading, when `check.py plan C-00001` runs, then it exits 1 and prints a problem naming T-0002 that contains `its commit subject would be 73 characters, limit 72` -- the PLAN.md title is measured, not the task file's heading — proven by integration test `the title measured is the one in PLAN.md`
- **A5** Given T-0001 of Type `feat` listed under a 50-character title that `check.py plan` passes, and whose module's tests pass, when `complete.py C-00001 T-0001` runs, then HEAD's subject is exactly `feat(C-00001/T-0001): <that title>`, 72 characters, neither truncated nor reworded — proven by integration test `a 72-character subject that passed the plan check is committed unchanged`

## Notes

- Shape (decided here, so T-0003 can reuse it): one function in
  `assets/scripts/checks.py` that, given the work id, task id, type and title,
  builds the subject exactly as `complete.py` does --
  `f"{type}({work_id}/{task_id}): {title}"` -- and returns the problem text, or
  nothing when it is 72 characters or fewer. The limit is a named constant (72,
  inclusive, as CI's `-gt 72`); length is `len()` in characters, as CI's
  `${#subject}`.
- Wording (decided here; T-0003 prints the same phrase): the plan check's
  problem line is
  `T-0002: its commit subject would be 73 characters, limit 72 -- shorten its title in PLAN.md`.
  Tests assert the phrase `its commit subject would be <n> characters, limit 72`.
  Alternative considered: printing the whole subject too -- rejected as noise;
  the number and the task id are enough to act on.
- Measure in `check_plan`, from the title in PLAN.md's task line (group 3 of
  `TASK_LINE`, what `complete.py` commits) and the Type in the task file. Skip
  the measurement when the Type is not one of `TYPES`: `check_task` already
  names that problem, and the subject is not known yet. The work id is the
  work item directory's name.
- The existing fixtures (`planned()` in `test/steps/kit.ts`) use the short
  title `Add GET /health`, so existing tests stay green. For A1-A3, build the
  plan with `planned([[1, null], [2, "T-0001"]])` and rewrite T-0002's line in
  PLAN.md; build titles of an exact length by padding real words, and assert the
  length in the test so a fixture slip shows up as itself.
- A5 already holds in today's `complete.py`, so its test will pass first time --
  a stop signal under `test-first`. Prove it can fail: temporarily truncate the
