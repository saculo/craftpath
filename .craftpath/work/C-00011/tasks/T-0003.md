# T-0003 — Refuse adding a task whose subject is too long

- **Work:** C-00011
- **Type:** feat
- **Wave:** 3
- **Depends on:** T-0001, T-0002
- **Touches:** assets/scripts/task.py, test/steps/plan.test.ts, .craftpath/scripts/task.py, .craftpath/manifest.json
- **Scenarios:** S5, S6

## Acceptance criteria

Every criterion starts from a plan for C-00001 (same length as C-00011)
created by `plan.py`, with T-0001 and T-0002 added by `task.py`; the next task
is T-0003, so a `refactor` prefix is 26 characters.

- **A1** When `task.py C-00001 --wave 1 --type refactor "<a 47-character title>"` runs, then it exits 1, prints a refusal naming T-0003 that contains `its commit subject would be 73 characters, limit 72` -- the phrase `check.py plan` prints -- creates no tasks/T-0003.md, and leaves PLAN.md byte-for-byte unchanged — proven by integration test `adding a task whose commit subject is too long is refused`
- **A2** When `task.py C-00001 --wave 1 --type refactor "<a 46-character title>"` runs (subject exactly 72 characters), then it exits 0, creates tasks/T-0003.md, and PLAN.md lists `- [ ] T-0003 — <that title>` under `### Wave 1` — proven by integration test `adding a task whose commit subject is exactly 72 characters succeeds`
- **A3** When `task.py C-00001 --wave 1 --type feat "<a 51-character title>"` runs (subject 73 characters with the shorter type), then it exits 1 and creates no tasks/T-0003.md -- the type given is the one measured — proven by integration test `adding a task measures its subject with the type given`

## Notes

- Measure with the function T-0001 added to `assets/scripts/checks.py`, given
  the work id, the task id about to be assigned, the `--type` value and the
  title, so `task.py` and `check.py plan` measure and word it identically
  (SPEC.md S5: "in the same words"). Do not write a second length rule.
- Wording (decided here): the refusal is
  `T-0003 is refused: its commit subject would be 73 characters, limit 72 -- shorten the title`.
  Alternative considered: printing the plan check's line unchanged, which ends
  "shorten its title in PLAN.md" -- rejected, nothing is in PLAN.md yet.
- Refuse after the task id is computed but before tasks/T-0003.md or PLAN.md is
  written. Validating the type (T-0002) comes first: an unknown type has no
  length to measure.
- The title measured is the one `task.py` will write into PLAN.md (the joined,
  stripped title), since that is the one `complete.py` commits.
- Assert the title's length in the test itself, so a fixture slip shows up as
  itself rather than as a wrong exit code.
- After changing `assets/`, run `bun bin/craftpath.ts init` in the worktree so
  the tracked installed copies under `.craftpath/` (and
  `.craftpath/manifest.json`) follow, and commit them with the task.
